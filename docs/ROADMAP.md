# План разработки — «На все котировки»

## Текущий статус
- Репозиторий создан: \`zority003-design/Market-Arena\`.
- Репозиторий приватный.
- Начинаем с документации и концепции; код игрового прототипа ещё не подтверждён.
- Технологический выбор предварительный: React + TypeScript + Vite и Three.js / React Three Fiber после проверки пригодности стека.

## Этап 0 — основа проекта
1. Зафиксировать игровой дизайн v0.1.
2. Зафиксировать каталог компаний и CEO.
3. Определить архитектуру папок и формат игровых данных.
4. Добавить README с целью проекта, запуском и статусом.
5. Вести журнал решений и изменений.

## Этап 1 — первый прототип
1. Поднять минимальное приложение.
2. Создать одну комнату общежития в 3D.
3. Добавить управление камерой и перемещение.
4. Добавить взаимодействие с компьютером.
5. Сделать интерфейс терминала с одной компанией.
6. Добавить одного клиента с профилем и памятью текущего разговора.
7. Добавить таймер ответа и шкалу доверия.
8. Сделать 6–10 вручную заданных ответов с различными последствиями.
9. Добавить итог сделки, комиссию и дневной отчёт.
10. Сохранять прогресс локально.

## Этап 2 — доказательство интересного игрового цикла
- 3–5 компаний с разными профилями риска.
- 5–8 клиентов с различными темпераментами.
- Новости, способные изменить разговор.
- Система подготовки к звонку.
- Отказ, повторный звонок и жалоба.
- Настройка таймера и баланса доверия.
- Проверка на повторяемость диалогов и понятность обратной связи.

## Этап 3 — расширение симуляции
- Генерация диалогов через ИИ с серверной защитой ключей.
- Память клиентов между звонками.
- Экономика фирмы и личные расходы.
- Улучшение жилья и офиса.
- Сотрудники и новые клиентские сегменты.
- Дополнительные компании, события и сюжетные цепочки.

## Этап 4 — полировка
- Звуки окружения и интерфейса.
- Анимации персонажей и реакций.
- Настройки графики.
- Оптимизация и проверка производительности.
- Автоматические тесты игровых правил.
- Подготовка к развёртыванию.

## Этап 5 — после подтверждения основной игры
- Голосовой ввод и озвучка.
- Несколько локаций.
- Сохранения в облаке.
- Кооператив и мультиплеер.
- Пользовательские сценарии.

## Принципы качества
- Не начинать с огромного мира.
- Не делать ИИ обязательным для локального теста.
- Не смешивать факты компании и выдумки генератора диалога.
- Не добавлять сложную функцию, пока основной цикл не интересен.
- Проверять сборку и основные сценарии после каждого этапа.
- Не писать в отчёте «готово», если функция не проверена.
- Хранить баланс в конфигурационных данных, а не в разрозненных компонентах UI.
